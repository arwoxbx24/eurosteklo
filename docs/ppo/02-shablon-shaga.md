# 02 Шаблон спецификации шага процесса (Евростекло)

Дата: 28.09.2026. Контур — только эта директория; портал не подключался; выгрузка `b24-export` не использована.
Методика: уровень L2 — действия, развилки, роли (`.claude/skills/process-mapping/SKILL.md:101-104`); исключения и дорожки обязательны (`process-mapping:204-205`); сначала «как сейчас», потом «как должно», с развилками, исключениями, сроками (`process-states/SKILL.md:83-89`); разрыв — класс процесс / технология / люди / данные (`gap-analysis/SKILL.md:39-45`), в цифрах, сверен с исполнителями (`gap-analysis:83-85`).
Статусы данных: **проверено** — кадр записи портала или выгрузка доски; **со слов** — доска директора, комментарий клиента, речь на записи без сверки с исполнителем; **нет** — источника нет. Ответов РОП пока нет (`docs/meetings/2026-09-28-встреча-РОП.md:93-136` — колонка «Ответ» пустая).

## 2. Правила заполнения
1. **ID** — «Ф<фаза>-<nn>» как в `docs/process/bpmn/data.md:16-24`; в скобках id узла схемы (`.agent-work/tz/004-inventory.md:27-44`).
2. **Название** — глагол + объект, дословно с доски; своё не придумывать.
3. **Фаза** — Ф1–Ф6 или ветка «Отказ» (`data.md:18-24`); номер этапа доски в скобках.
4. **Триггер** — событие-запуск: переход стадии, оплата, документ, срок; нет — «нет данных → вопрос».
5. **R** — одна роль; две роли → шаг разбить.
6. **A** — одна роль; «контролирует» на доске — вывод аналитика, не факт.
7. **C** — с кем согласуют до завершения (юрист, бухгалтер, руководители).
8. **I** — кому уведомление; источник — комментарии клиента (`docs/specifications/2026-09-28-eurosteklo-spec.md:266`).
9. **Предусловия** — что истинно до старта: документ, оплата, заполненное поле.
10. **Действия** — нумерованный список, каждое из узла доски со ссылкой.
11. **Постусловия** — проверяемый факт в системе: «файл загружен», «поле заполнено», «стадия = X».
12. **Документы: вход** — только из списка `spec.md:102-110`.
13. **Документы: выход** — что шаг создаёт или передаёт.
14. **Срок: норма** — число из источника; нет — «нет данных».
15. **Срок: факт** — измерение (экран, отчёт, исполнитель); оценки не допускаются.
16. **AS-IS** — что видно в портале (кадр/таймкод) + слова исполнителя.
17. **TO-BE** — доска и комментарии директора; решения аналитика — «предложение».
18. **Разрыв** — AS-IS минус TO-BE, класс по `gap-analysis:42-45`, по возможности цифрой.
19. **Исключения** — отказ, неоплата, нестандартный документ, возврат назад; у каждого — куда уходит поток.
20. **Подвохи** — что сорвёт шаг или исказит данные, со ссылкой.
21. **Регламентация** — «строго» при числе, «обязательно» или деньгах в источнике, иначе «гибко»; обоснование одной фразой.
22. **Сущность Б24** — AS-IS (по кадру) и TO-BE (кандидат, не утверждён; сверка по `04-b24-arhitektura.md`). Настройку Б24 не выполнять.
23. **Статус данных** — по ключевым полям; одно «со слов» не повышает статус карточки.
24. **Открытые вопросы** — «вопрос → роль»; если вопрос есть в интервью — номер из `встреча-РОП.md` / `03-oprosnik-v2.md`.

## 3. Пример 1. Замер
| поле | значение и источник |
|---|---|
| ID | Ф2-01; узлы t1 «Счёт за замер + задание», t2 «Контроль замера» (`004-inventory.md:30-31`) |
| Название | Замер и проектирование (платный замер) (`встреча-РОП.md:35`) |
| Фаза | Ф2 «Расчёт и замер», этапы доски 1 «Предварительный расчёт», 2 «Заявка» (`data.md:19`); отдельного этапа «Замер» на доске нет (`data.md:28`) → директору |
| Триггер | нет данных → РОП Б1: что должно произойти, чтобы сделка дошла до замера (`встреча-РОП.md:104`) |
| R | Менеджер ОП: счёт на замер, контроль оплаты, задание (`data.md:36-37`); Руководитель ПО: распределение, контроль замера и проектирования (`data.md:38`). Две роли → на L3 разбить на Ф2-01a / Ф2-01b |
| A | нет данных → директору; «контролирует» Рук. ПО (`data.md:38`) — вывод аналитика |
| C | нет данных → Руководителю ПО |
| I | Руководитель ПО — уведомление (комментарий …7352, `spec.md:266`); остальные — нет данных |
| Предусловия | сделка создана из лида, реквизиты в карточке компании (`data.md:32`); позиции в «Товарах» (`data.md:33`). «Задание только после оплаты» в источнике нет, есть только связь счёт → задание (`spec.md:127-128`) → РОП Б2 (`встреча-РОП.md:105`) |
| Действия | 1. Менеджер ОП выставляет счёт за замер, контролирует оплату (`spec.md:89`). 2. Формирует задание на замер (`spec.md:93`, `:129`). 3. Рук. ПО распределяет, контролирует замер и проектирование (`spec.md:99`, `:131`). 4. Готовятся чертежи и спецификации (`spec.md:132`) |
| Постусловия | предложение: в сделке загружены чертёж DXF и PDF, спецификации фурнитуры и расходников, монтажная схема PDF (`data.md:39`); клиентом не утверждено → Руководителю ПО |
| Документы: вход | счёт на оплату замера, «Предварительная оценка» (`data.md:36`; `spec.md:105-106`; связь `spec.md:129-130`) |
| Документы: выход | чертёж DXF/PDF, спецификации фурнитуры и расходников, монтажная схема PDF (`data.md:39`; `spec.md:132`) → вход «Заказ в производство» (`spec.md:133-134`) |
| Срок: норма | нет данных → директору |
| Срок: факт | нет данных → РОП Б7 (`встреча-РОП.md:110`); на записи: «многие вещи остаются длительно на процессе» (`as-is.md:36`) |
| AS-IS | воронка «Активные продажи», стадия «Замеры и проектирование» — 17 сделок; на «Предварительной заявке» 1166 (`as-is.md:31,34`); поля «Чертежи», «файлы чертежей», «Укажите_примерные_размеры…» пустые (`as-is.md:45-47,99`); роли ПО и Менеджер ОП в портале не видны (`as-is.md:83`) |
| TO-BE | счёт → задание → Рук. ПО → документы (`data.md:35-39`); уведомление Рук. ПО (…7352) |
| Разрыв | процесс: 17 на замере при 1166 на заявке — снимок, не конверсия (`B-oprosnik-rop.md`); люди: роль ПО в портале не видна (`data.md:82`, P8); данные: поля чертежей пустые (`as-is.md:99`); технология: уведомлений Рук. ПО не видно (`as-is.md:191`) |
| Исключения | отказ в группе «Замер и проектирование» (…7339, `spec.md:269`; `as-is.md:178`) — с какого узла, уточнить; причины — `data.md:64`; замер не оплачен — нет данных → РОП Б2 |
| Подвохи | 1. две воронки, какая рабочая — неизвестно (`data.md:83`, P9). 2. стадия портала объединяет замер и проектирование, на доске стадии нет (`as-is.md:31`; `data.md:28`). 3. этапы доски не соединены стрелками (`data.md:28`) |
| Регламентация | строго: оплата и состав документов (платный замер `встреча-РОП.md:35`; список `data.md:39`); гибко: распределение внутри ПО — правил нет |
| Сущность Б24 | AS-IS: стадия «Замеры и проектирование», поля «Чертежи», «файлы чертежей» (`as-is.md:31,47`); роботы стадий — через дизайнер (`as-is.md:56`). TO-BE кандидат: уведомление Рук. ПО; стадия или смарт-процесс «Замер» — решения нет |
| Статус данных | действия и документы — проверено (связи доски `spec.md:127-132`); стадия и 17 сделок — проверено (кадр `as-is.md:34`); роли, A, сроки, критерий — со слов / нет |
| Открытые вопросы | 1. кто выезжает на замер, кто выставляет счёт → РОП (Б2). 2. что мешает дойти до замера → РОП (Б1). 3. критерий «замер завершён» и норма срока → Рук. ПО. 4. отдельная стадия «Замер» в целевой воронке → директор |

## 4. Пример 2. Предоплата и договор
| поле | значение и источник |
|---|---|
| ID | Ф3-01; узлы t3 «Договор, предоплата» (Менеджер ОП), c1 «КП, подпись, оплата» (Клиент) (`004-inventory.md:32-33`) |
| Название | Договор, подписание, предоплата |
| Фаза | Ф3 «Договор и оплата», этапы доски 3 «Договор», 4 «Подписание», 5 «Предоплата» (`data.md:21`) |
| Триггер | на схеме — завершён Ф2 (ed3 t2 → t3, `004-inventory.md:53`); порядок этапов доски не подтверждён (`data.md:28`) → директору |
| R | Менеджер ОП (`data.md:43-45`) |
| A | нет данных → директору |
| C | юрист: договор на согласование правок (`data.md:43`); типовую форму согласовать с юристом и бухгалтером (…7357, `spec.md:241`) |
| I | Менеджер ОП — напоминание через 2–3 дня (`data.md:46`); остальные — нет данных |
| Предусловия | «Товары» заполнены → из них КП, типовой договор, спецификация (`spec.md:122-124`); реквизиты компании (`data.md:32`) |
| Действия | 1. договор юристу, согласовать правки, сформировать договор, ПР, ПСР (`spec.md:90`). 2. договор заказчику (`spec.md:88`). 3. загрузить скан, подписанный обеими сторонами (`spec.md:91`). 4. счёт на предоплату (`spec.md:91`). 5. контроль предоплаты ≥35 % (`data.md:46`) |
| Постусловия | предложение: скан подписанного договора загружен (`data.md:45`), предоплата ≥35 % получена (`data.md:46`); что значит «получена» (1С, выписка) — нет данных → РОП Г2 (`встреча-РОП.md:126`) |
| Документы: вход | типовые формы КП и договора, спецификация к договору из «Товаров» (`data.md:42`) |
| Документы: выход | скан подписанного договора; ПР и ПСР (расшифровки нет, `as-is.md:218`); счёт на предоплату (`004-inventory.md:87-88`) |
| Срок: норма | напоминание через 2–3 дня; смена этапа «Договор» через 3 рабочих дня (`data.md:46`; …7341, …7342, `spec.md:267`); от какого события — нет данных → директору |
| Срок: факт | нет данных → РОП Б7 (`встреча-РОП.md:110`) |
| AS-IS | в «Активных продажах» нет стадий «Договор», «Подписание» (`as-is.md:116-117`); есть «Согласование сделки» (1 сделка) и «Оплата» (39 сделок) (`as-is.md:34`); «Предоплата» не показана (`as-is.md:118`); кнопка «Принять оплату» (`as-is.md:48`), 1С-поле «Заказ оплачен (624)» (`as-is.md:47`), триггер «Отследить оплату…» (`as-is.md:55`); поле «КП» пустое (`as-is.md:88`) |
| TO-BE | три стадии доски, предоплата ≥35 %, напоминание и автосмена стадии (`data.md:46`; FR-012 `spec.md:240`); документы автоматически (FR-013 `spec.md:241`) |
| Разрыв | процесс: нет стадий «Договор», «Подписание», «Предоплата» (`data.md:77`, P3); технология: SLA-таймеров не видно (`as-is.md:180`); данные: документов в портале не видно (`as-is.md:88`) |
| Исключения | 1. договор по форме заказчика (…7358, `spec.md:271`). 2. отказ с шага: ed16 t3 → «Отказ», «откуда — уточнить» (`004-inventory.md:66`); причины `data.md:64`. 3. предоплата <35 % — нет данных → директору |
| Подвохи | 1. где фиксируются договор и предоплата: Б24, 1С или бумага (`встреча-РОП.md:106`, Б3). 2. «смена этапа через 3 рабочих дня» — автопереход или срок? уточнить. 3. ПР, ПСР — расшифровка неизвестна (`as-is.md:218`). 4. оплату может отмечать 1С, не менеджер (`as-is.md:47`) |
| Регламентация | строго: число (≥35 %), срок (3 раб. дня), обязательные документы (`data.md:42,46`); гибко: правки юриста и форма заказчика (`spec.md:271`) |
| Сущность Б24 | AS-IS: стадии «Согласование сделки», «Оплата», кнопка «Принять оплату», поле «Заказ оплачен (624)», триггер «Отследить оплату…» (`as-is.md:31,47-48,55`). TO-BE кандидат: стадии «Договор», «Подписание», «Предоплата», робот-напоминание 2–3 дня, автосмена стадии, шаблоны документов (FR-012, FR-013); права на смену стадии — нет данных |
| Статус данных | действия — проверено (узлы доски `spec.md:88-91`, связь `spec.md:122-124`); стадии и цифры портала — проверено (кадр); 35 % и сроки — со слов (комментарий клиента); A, факт срока, критерий оплаты — нет |
| Открытые вопросы | 1. где отмечаете договор, подписание, предоплату → РОП (Б3). 2. КП, договор, счета — в Б24 или отдельно → РОП (Г5). 3. кто утверждает скидку / предоплату <35 % → директор. 4. что такое ПР и ПСР → РОП. 5. от какого события 3 рабочих дня → директор |
