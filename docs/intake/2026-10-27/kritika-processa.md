Тезис «Роман хочет максимально упрощённый и автоматизированный процесс, следовательно обмен в обе стороны»:
- «Упрощённый» — да (T1-179, T2-264 «максимально упростим»).
- «Автоматизированный» — не везде, и это важно: «изготовлено» — вручную, «автоматику не вносим» (T2-271, 275); отказники из расчёта — вручную (T2-151, 161); уход лида в отказники — вручную (T2-173); отгрузка без оплаты — РОП вручную (T2-321); календарь 1С с Битрикс24 синхронизировать «не обязательно» (T3 52:31).
- «Следовательно, в обе стороны» — не следует. Роман хочет, чтобы действие менеджера в Битрикс24 отражалось в 1С (T1-53–55) — это направление Б24 → 1С для стадий продажи. И чтобы оплата и «изготовлено» из 1С были видны в Битрикс24 (T2-236, 277) — направление 1С → Б24 для учётных событий. Это не «двусторонний обмен одного статуса», а два разных потока по разным событиям. Двусторонняя синхронизация одного и того же поля — ровно то, что Дмитрий (27.10) и типовой обмен КА не делают.

## B. Блокировка одновременного изменения статуса

Что просит менеджер: если один заказ существует как сделка в Битрикс24 и как заказ в 1С под одним идентификатором, при попытке
изменить статус с двух сторон одновременно — блокировать.

Разбор:
- Клиент такого случая не описывал. Он описал обратное: один ответственный на сделку (T2-127–131), один человек ведёт.
- Конфликт «два менеджера на одной сделке» в Битрикс24 решается правами, а не блокировками: стадии двигает только ответственный,
  права на стадии по ролям (ролевая модель CRM — UNVERIFIED по тарифу, проверить на G2).
- Конфликт «Битрикс24 vs 1С на одном поле» решается разделением владения: у каждого статуса один владелец. Стадии продажи
  (расчёт → договор → подписание → предоплата) владеет Битрикс24, 1С их не трогает. Учётные состояния (оплата получена,
  в производстве, изготовлено, реализация проведена) владеет 1С, Битрикс24 их только принимает. Тогда «одновременно изменить»
  невозможно по построению — блокировать нечего.
- Если всё же оставить одно поле с двумя писателями, нужен арбитраж (кто последний / чей приоритет) — это ровно та «интеграция-монстр», о которой менеджер сам предупреждал клиента (T2-247, T3 58:49).

Вывод: регламентировать можно, но не как блокировку, а как правило владения. Технически в Битрикс24: обязательные поля по
стадиям + роботы/триггеры по выполненным задачам + права по стадиям; со стороны 1С — только выгрузка состояний по
расписанию (типовой обмен КА 2.5, со слов Дмитрия; на конфигурации клиента — проверить).

## C. Связка двух платформ — крупными мазками

```
ВХОД              БИТРИКС24 — ПРОДАЖА                      1С КА — УЧЁТ И ПРОИЗВОДСТВО
──────            ────────────────────────────────────────  ─────────────────────────────────────
салоны, сайт,  →  ЛИД: наш/не наш, дубли, карточка          контрагент создаётся ОДИН раз (1С)
Telegram, MAX,    ↓ сразу                                    ← заказ клиента (из сделки или в 1С — решить)
ВК, почта         СДЕЛКА: Предварительный расчёт   ───────→ КП, договор, счёт формируются в 1С
                    задачи ПО: оценка, чертёж, спецификации  → PDF в сделку (1С → Б24)
                  Договор → Подписание (3 дня) → Предоплата ← оплата разнесена (1С → Б24: факт, сумма)
                  Производство                            ← «в производстве» / дата готовности (1С → Б24)
                  Изготовлено (ПТО ставит вручную в 1С)   ← «изготовлено» (1С → Б24)
                  Отгрузка: чек-лист, УПД, доверенность   ← реализация, УПД (1С → Б24: документы)
                  На монтаже (если есть): схема, наряд, акт  задания монтажа — только Битрикс24
                  Завершена → звонки 14/90/270 (ассистент)
ОТКАЗНИКИ         отдельная воронка, вручную, с причиной
```
Направления: Б24 → 1С — контрагент и заказ при создании сделки (если так решим), стадии продажи не передаются как статусы.
1С → Б24 — документы, оплата, производственные состояния. Ни одно поле не пишется с двух сторон.

Роли и кто какой статус двигает:

| Роль | Где работает | Что двигает |
|---|---|---|
| Менеджер салона / ОП | Битрикс24 (+ 1С для документов) | лид → сделка; расчёт → договор; галочки «замер», «монтаж»; наряд на монтаж |
| РОП | Битрикс24 | онлайн-лиды → менеджерам; решения: отказник, отгрузка/монтаж без оплаты |
| Руководитель проектного отдела | Битрикс24 (задачи) | замер, 5 документов; без них сделка стоит |
| Руководитель ПТО | 1С (через окно из Б24 — по выбору) | дата готовности в график; «изготовлено»; приём документов от водителя |
| Руководитель снабжения | Битрикс24 (календарь) + 1С | срок поставки фурнитуры; «на складе» |
| Руководитель службы сервиса | Битрикс24 | монтаж: готовность объекта, перенос, акт |
| Ассистент ОП | Битрикс24 | закрывающие, оригиналы, завершение сделки, звонки 14/90/270 |
| Юрист | Битрикс24 (задача, 3 дня) | договор не по нашей форме |
| Бухгалтерия | 1С | разносит оплату → факт уходит в Б24 |

Статусная модель — одна, названия приводит клиент (T3 49:44): стадии Битрикс24 = ориентир, лишние статусы 1С скрываются.
Ключ связи: номер заказа 1С ↔ ID сделки Битрикс24, хранится с обеих сторон (из чата 1С 27.10; типовой приём).

## Что в этом остаётся нерешённым (внутреннее)
1. Где рождается заказ клиента: в 1С вручную (как сейчас) или создаётся из сделки Битрикс24. Роман: документы «подтягивать из 1С» (T2-24), но «менеджеру нужно будет в 1С что-то сделать» (T2-21–22) он принял. Это решает, нужно ли направление Б24 → 1С вообще.
2. Типовой обмен КА 2.5 или доработка — только на конфигурации клиента.
3. Права на стадии по ролям и обязательность полей от стадии — зависят от тарифа; «Профессиональный» — проверить на G2.
