## 2. Пять новых идей (с учётом цикла 1)

- **Н1. Метки внутри пункта вместо атрибутов** (`small.src` / `small.see`): регэкспы движка и CK не меняются, правка — 2 места (разрешение спора 3).
- **Н2. Ключ флажка — хеш текста пункта** (`data-if="h3f9a1c"` вместо позиции, BP:192). Ключ не сдвигается, когда удаляются дубли, и разметка не нужна. JS (BP:268) берёт ключ как строку, выгрузка `.md` идёт по тексту подписи — совместимо. Старые позиционные записи просто не найдут пару.
- **Н3. Повестка = порядок `top5`.** Точки чужого процесса пишутся только полным путём (`../sdelki/obsledovanie-sdelki.html#t1`): тогда регэксп `href="#t(\d+)"` их не примет за т.1 лидов.
- **Н4. Чистка клиентского текста по стоп-словам:** «не собственник», «должен знать», «много … ошибок», «уволено», «не истина». При приёмке grep по собранным `*.html` должен дать 0. Движок не меняется.
- **Н5. Накопитель аудита лидов** `lidy/_parts/audit-lidy.md` (по образцу `sdelki/_parts/audit-B|C.md`). Каждая портальная фраза, снятая по H-3, переносится туда дословно, с номером точки. Решение 28.09 «копим для аудита» выполняется, знание не теряется.
