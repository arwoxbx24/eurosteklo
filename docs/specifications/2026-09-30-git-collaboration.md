**Создана**: 30.09.2026 Codex CLI (PR №1, коммит `eff23fb`) · **Доработана**: Claude Web 30.09.2026 по итогам проверки · **Основание**: запрос владельца о совместной работе трёх агентов (Codex CLI, Claude CLI, Claude Web): разные ветки, у всех актуальные данные, общий мозговой штурм, точки отката, сохранение истории; решение владельца 30.09: «выбрать лучшее архитектурное решение, не останавливаться».
**Статус**: действует.

## Цель и границы

Цель — дать трём изолированным агентам, работающим в разное время, одну общую проверяемую версию, место для общих гипотез и возможность вернуться к принятому состоянию, ничего не ломая.

- Правило относится только к репозиторию `arwoxbx24/eurosteklo` (закон жёсткого контура): его не выносят и не масштабируют на другие проекты. Битрикс24 не затрагивается.
- В Git хранятся только разрешённые обезличенные материалы и производные документы. `client-materials/private/`, выгрузки CRM, секреты и база Beads в Git не попадают и ветками не синхронизируются (П10). Из одного `git pull` не следует, что локальные каталоги на разных машинах одинаковы.
- Регламент касается только Git. Изменение клиентских документов по-прежнему идёт по закону ТЗ и RG-001 (П11).

## Решение

```
  docs/idei/codex/  docs/idei/claude-cli/  docs/idei/claude-web/   (каждый пишет в свою, читают все)
            \                 |                  /
  codex/2026-10-01-x    claude-cli/2026-10-02-y    claude/<имя-от-платформы>
   (сессия Codex CLI)    (сессия Claude CLI)        (сессия Claude Web)
            \                 |                  /
             PR → merge-коммит (только в одну сторону: ветка → main)
                              v
  main ──●──────●──────────●──────────●──►  (история только дописывается)
         575a157            \
         checkpoint/2026-09-30-lidy-sdelki  + строка в docs/CHECKPOINTS.md
                              |
  codex/8b44-eurosteklo ──── fast-forward до main (зеркало, пока default не переключён)
```

**П1. Ствол.** `main` — единственная общая ветка. Ветку по умолчанию на GitHub переключает на `main` владелец (Settings → General → Default branch). До переключения `codex/8b44-eurosteklo` — замороженное зеркало `main`: в неё никто не коммитит, её только перематывают fast-forward до `main` после каждого слияния.

**П2. Ветка на этап.** Каждый этап работы — своя ветка от свежей `origin/main`, имя `<агент>/<ГГГГ-ММ-ДД>-<этап>-<суть>` (агент: `codex`, `claude-cli`, `claude-web`; например `claude-web/2026-09-30-e3-dvizhok-otvety-roli`). Ветку, которую выдаёт веб-платформа (`claude/<случайное-имя>`), Claude Web использует только для служебного; работа по этапам — в ветках с понятными именами (проверено 30.09: платформа их пропускает). В чужую ветку не пишет никто. Автор коммитов — своё имя в своём клоне: `git config user.name "Codex CLI"` / `"Claude CLI"` / `"Claude Web"`. Указание владельца 30.09.2026: «все процессы регистрировать в ветках GitHub, чтобы всё можно было откатить; адекватные названия веток».

**П3. Начало сессии.** `git status` (чисто) → `git fetch origin` → `git switch -c <имя> origin/main` (если своя ветка не закончена — `git merge origin/main` в неё). Прочитать `AGENTS.md`, `docs/ppo/HANDOFF.md`, журнал решений (`docs/ppo/00-resheniya-vladeltsa.md`), `docs/CHECKPOINTS.md`, свежие файлы `docs/idei/*/`.

**П4. Конец сессии.** Проверки: `git diff --check`; поиск ПДн (телефоны, e-mail, фамилии) = 0; если трогали `docs/ppo` — `python3 docs/ppo/build_all.py`. Затем push своей ветки → PR в `main` → слияние merge-коммитом (не squash, не rebase); сливает сам агент в конце своей сессии → fast-forward `codex/8b44-eurosteklo` до `main` (пока default не переключён) → запись в `docs/CHECKPOINTS.md`, если закрыт этап. Исключение: изменения клиентских документов (`docs/ppo/**`, кроме `HANDOFF.md`; ТЗ; карты) сливаются только после «да» владельца, до этого PR остаётся открытым. Идеи и служебные файлы агент сливает сам.

**П5. Мозговой штурм.** Папки `docs/idei/codex/`, `docs/idei/claude-cli/`, `docs/idei/claude-web/`: каждый агент пишет только в свою, читают все. Файл `ГГГГ-ММ-ДД-<тема>.md`; в шапке — статус ИДЕЯ | ГИПОТЕЗА | ПРИНЯТО ВЛАДЕЛЬЦЕМ | ОТКЛОНЕНО, источники, метки PROVEN/INFERRED/UNVERIFIED по закону блокировки. Отклик на чужую идею — файлом в своей папке со ссылкой на неё. Идеи попадают в `main` сразу (их видят все), в клиентские документы — только после «да» владельца.

**П6. Общие файлы.** `AGENTS.md`, `CLAUDE.md`, `docs/ppo/HANDOFF.md`, `docs/ppo/00-resheniya-vladeltsa.md`, `client-materials/sanitized-*.md`, `docs/ppo/_common/`, `docs/CHECKPOINTS.md` в каждый момент правит одна сессия; журнал решений и реестр точек — только дописываются. Конфликт в собранных HTML решается в `_parts/` с пересборкой `python3 docs/ppo/build_all.py`; HTML вручную не склеивают.

**П7. Дробление внутри сессии.** Параллельные блоки одной сессии (закон дробления) пишут разные файлы в одном рабочем дереве — разрешено. Двум разным сессиям писать в одну ветку запрещено. Отдельный `git worktree` нужен, только если на одной машине одновременно идут две сессии.

**П8. Точки отката.** Метки ставит CLI-агент (Claude Web не может их отправить). Реестр `docs/CHECKPOINTS.md` (дата, метка, полный SHA, что утверждено) + аннотированная метка `checkpoint/<ГГГГ-ММ-ДД>-<этап>` на `main`. Метки не двигают и не удаляют; при сомнении верят полному SHA из реестра (метка без серверной защиты — навигация, не резерв). Откат — только `git revert` новым PR. Force-push и переписывание истории `main` запрещены; единственное исключение — удаление персональных данных по решению владельца.

**П9. Старые локальные копии** (история до чистки 29.09): ничего из них не пушить и не вливать; `reset --hard`, cherry-pick и автоматический merge не применять. Порядок: `git status` → `git branch backup/<ГГГГ-ММ-ДД>-old HEAD` (только локально, никогда не пушить — в старой истории есть ФИО) → `git fetch origin` → `git switch -c <новая ветка> origin/main` → незаконченные правки переносить вручную, с проверкой на ПДн.

**П10. Вне Git.** `client-materials/private/`, база Beads, выгрузки CRM, ключи. Git их не синхронизирует; передаёт владелец отдельно. Beads — рабочий инструмент Codex CLI, для Claude не обязателен; источник истины о состоянии — репозиторий (`HANDOFF`, `CHECKPOINTS`).

**П11. Границы регламента.** Регламент касается только Git. Изменение клиентских документов идёт по закону ТЗ и RG-001 (spec 001): ТЗ → `/ce-doc-review` → `code-channel`; Git — транспорт, а не замена этому порядку. Законы `CLAUDE.md` и `AGENTS.md` (дробление, согласование, жёсткий контур, блокировка) действуют без изменений.

## Порядок сессии (шпаргалка)

```bash
# начало
git status                                   # должно быть чисто
git fetch origin
git switch -c claude-cli/2026-10-01-sut origin/main   # или: git merge origin/main в свою незаконченную ветку
# конец
git diff --check && python3 docs/ppo/build_all.py      # сборка — если трогали docs/ppo
git push -u origin HEAD
# PR в main → слияние merge-коммитом (клиентские документы — после «да» владельца)
git fetch origin && git push origin origin/main:codex/8b44-eurosteklo   # зеркало, только fast-forward
git tag -a checkpoint/2026-10-01-etap -m "что утверждено" origin/main && git push origin checkpoint/2026-10-01-etap  # если закрыт этап + строка в docs/CHECKPOINTS.md
```

## Открытые вопросы владельцу (действия только владельца)

1. Переключить ветку по умолчанию на `main`: GitHub → Settings → General → Default branch. После этого зеркало `codex/8b44-eurosteklo` больше не перематывается.
2. Запрос в поддержку GitHub об удалении недоступных из веток коммитов `fd1bbeb9649a…` и `7544309` (и кэшированных представлений) — в них файл сотрудников с полными ФИО. Пока запрос не выполнен, риск открыт.
3. Серверная защита веток и меток на текущем тарифе недоступна (со слов Codex CLI, UNVERIFIED): риск прямого push в `main`, сдвига или удаления меток закрыт только правилами П1, П8. Принять риск или сменить тариф — решение владельца.

Справка по механике: [git worktree](https://git-scm.com/docs/git-worktree) — несколько рабочих деревьев одного репозитория; [git revert](https://git-scm.com/docs/git-revert) — отмена изменений существующего коммита новым коммитом; [GitHub protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches) — запрет force push и удаления при включённом правиле (в «Евростекле» не включено, см. таблицу состояния).
