# Итог: подход ППО → спецификация → облачный Б24. Критика и самопроверка

Атом eurosteklo-k5d, 28.09.2026. Сведение блоков: [A — данные](A-dannye.md), [B — опросник РОП](B-oprosnik-rop.md), [C — навыки](C-navyki-instrumenty.md).

## 1. Критика подхода владельца
| тезис владельца | вердикт | почему |
|---|---|---|
| Дробить ППО, регламентированный опросник | верно | стандарт elicitation (`.claude/skills/requirements-elicitation`); без регламента ответы несравнимы |
| Архитектурно составить вопросы | верно, но не хватает оси «доказательство» | блок B: из 22 вопросов 0 требуют артефакт (ID сделки, отчёт); ответ по памяти не проверить |
| Спека «как сейчас / как должно / подвохи / пред-, постусловия / варианты» | верно | это шаблон use case / process-states; добавить: триггер, срок, владелец, сущность Б24 |
| Кто за что отвечает, что регламентировано | верно | RACI, один A на стадию (`stakeholder-analysis:99`) |
| Сразу под Б24, а не абстрактный БП | верно и главное | каждый ответ должен лечь в сущность: воронка, стадия, поле, смарт-процесс, робот, БП, право |
| Всё спросить у РОПа | **ошибка** | ~40 % вопросов — чужая зона (ПО, ПТО, сервис, бухгалтерия, 1С); интервью по ролям M1–M7 (блок B) |
| Процесс собирать со слов | **ошибка** | сначала данные портала (M0), потом интервью — сверяем слова с фактом, а не наоборот |

## 2. «Пять почему»: почему нельзя сейчас прогнать всю спецификацию
1. Почему нельзя? — 16 из 20 требований «частично», 4 «нет» (блок A).
2. Почему частично? — данные только с доски директора и 7 мин записи экрана интегратора; людей не опрашивали.
3. Почему не опрашивали? — встреча с РОП подготовлена, но не проведена/не записана (транскрипт 0 байт, 22 из 32 ответов пусты).
4. Почему нельзя добрать из Б24? — нет доступа к порталу клиента: выгрузка и MCP — портал интегратора (проверено `deal_category_list`).
5. Почему нет доступа? — read-only вебхук портала клиента не выдан. **Корень: нет двух входов — доступа к порталу клиента и интервью по ролям.**

## 3. «Вру / не вру»: проверка собственных утверждений
| утверждение | проверка | итог |
|---|---|---|
| навыки бизнес-анализа установлены | `ls .claude/skills` → 13 навыков | правда |
| навыка под архитектуру Б24 нет | прошлый поиск + 5 кандидатов блока C, ни один не читает роботы/права | правда (на 28.09) |
| выгрузка Б24 — не клиента | `spec.md:150-155` + `deal_category_list` → воронки интегратора | правда |
| слова клиента есть | `ls -la transcription` → транскрипт 0 байт | ложь — их нет |
| dev-MCP Б24 даёт данные | apidocs.bitrix24.ru/ai-tools/mcp.html: «не читает и не изменяет лиды, сделки, задачи и файлы» | ложь — только документация |
| навыки из `clients/` подхватятся | code.claude.com/docs/en/skills: «…in every parent directory up to the repository root»; корень eurosteklo = сам eurosteklo | ложь — не подхватятся |

## 4. Вердикт
**Не подтверждаю, что можно прогнать спецификацию полностью.** Методика и навыки — хватает (13 навыков БА + speckit + drawio-ai-kit). Данных — не хватает.
Что нужно, по порядку:
1. Read-only вебхук портала клиента `evrosteklo.bitrix24.ru` (права: crm, bizproc, user) → секрет в `/root/workspaces/secrets/` → чтение структуры: воронки, стадии, поля, смарт-процессы, шаблоны БП, история стадий, объёмы. Закрывает №7, 11–14, 16, 18.
2. Опросник v2 по ролям M0–M7 с шаблоном «триггер → шаги → предусловие → результат → исключения → документ → срок → R/A → доказательство → сущность Б24» (блок B).
3. Интервью с записью по ролям → закрывает №1–10, 15, 17, 19, 20.
4. Справочник REST — подключить официальный dev-MCP `https://mcp-dev.bitrix24.tech/mcp` (без ключей, только документация) — чтобы сопоставление «ответ → сущность Б24» ссылалось на документацию, а не на память.

Навыки искать не нужно, кроме dev-MCP: кандидаты блока C дублируют установленное или не про архитектуру CRM.

## 5. Где хранить навыки
Сейчас — в `eurosteklo/.claude/skills` (штатно грузятся). `clients/.claude/skills` при старте из eurosteklo **не грузится** (другой git-репозиторий). После утверждения подхода — отдельное решение о масштабировании: шаблон-репозиторий клиента с набором навыков, либо личные `~/.claude/skills`.
