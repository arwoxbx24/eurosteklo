## 3. Что считается находкой

- **РАЗРЫВ ДАННЫХ** — шаг, статус, роль или точка есть в одном документе и пропала или оборвалась в другом: например,
  точка N есть в `TOCHKI.md`, но её нет на карте; переход ведёт в никуда.
- **НЕСООТВЕТСТВИЕ** — два места в объёме говорят разное об одном и том же: другое число, порядок, роль, SHA, статус.
- **ФАЛЬСИФИКАЦИЯ** — утверждение подано как факт («проверено», «совпадает», «клиент подтвердил»), но источник в объёме,
  на который оно ссылается, говорит другое, или ссылка ведёт на файл, которого нет в репозитории.
- **ПОДТВЕРЖДЕНО** — блок проверен и верен. Доказательство такое же, как у ошибки.
- **НЕ ПРОВЕРЕНО** — проверить нельзя. Если утверждение ссылается на доску Miro, встречу или иной внешний источник,
  это НЕ ПРОВЕРЕНО с пометкой «внешний источник: <какой>», а не ФАЛЬСИФИКАЦИЯ.

Серьёзность:
- **S1** — на встрече клиент увидит неверное или процесс не сходится. Примеры: точки нет на карте; переход ведёт в
  несуществующий шаг; на двух страницах разная роль у одного шага; утверждение «клиент подтвердил» без источника.
- **S2** — искажение, которое заметит внимательный читатель. Примеры: разное число точек в шапке и в таблице; неверный
  SHA метки; ссылка на файл, который переименован.
- **S3** — косметика: опечатка, разный регистр, лишний пробел в названии.

## 4. Формат файлов A–D

Имена файлов фиксированы: `A-glavnaya.md`, `B-sdelki.md`, `C-lidy.md`, `D-konflikty.md` в каталоге
`docs/review/2026-10-01-codex-vtoroe-mnenie/`.

1. **Шапка:** блок; вывод `git rev-parse HEAD`; строка `skills: …` — навыки, которые ты реально вызвал, и для каждого
   его след: файл-артефакт (раздел 7).
2. **Таблица «Прочитано»:** все файлы объёма блока по `git ls-files <путь>` — файл, число строк (`wc -l`), прочитан
   да/нет; для «нет» — причина. Файл, которого нет в этой таблице, нельзя упоминать в находках.
3. **Матрица покрытия** — только для B и C: одна строка на каждую точку процесса из `_parts/TOCHKI.md`
   (точка → место на карте → место в состояниях → класс). В шапке — число точек и команда, которой ты их посчитал.
   Число строк матрицы равно этому числу. Пропуск точки = блок не закончен.
   **Для D — матрица связей:** по одной строке на каждый конфликт из `k1-prepost.md`, `k2-forks.md`, `k3-conflicts.md`
   (где отражён на карте сделок и карте лидов → класс) и на каждую связь: главная ↔ сделки (названия процессов, граница
   «лид / сделка»), главная ↔ лиды, лиды → сделки (передача лида в сделку).
   **Независимость:** сначала матрица и находки по первичным файлам (точки, карты, состояния, конфликты), и только потом
   чтение прежних проверок (`proverka-2026-09-30/*`, `FACTCHECK-*.md`, `audit-*.md`). Расхождения своих выводов с
   прежними — отдельная таблица «Расхождения с прежней проверкой».
4. **Таблица находок:**

| ID | Класс | S | Файл:строка | Дословная цитата | Противоречит (файл:строка + цитата) | Что сломается на встрече | Предложение |
|---|---|---|---|---|---|---|---|

   - ID: `A-01`, `B-01` и т. д.
   - Цитата — дословная подстрока строки файла, до 200 символов.
   - Строка длиннее 400 символов (так бывает в HTML-картах, например JSON `mapdata`): в графе «Файл:строка» укажи строку
     и идентификатор внутри неё (`id="p24"`, `"24":`), а цитату бери вокруг этого идентификатора.
   - Символ `|` внутри цитаты записывай как `\|`.
   - Для ПОДТВЕРЖДЕНО в графе «Противоречит» пишется, с чем сверено (файл:строка + цитата).
5. **Самопроверка:** каждая цитата проверена командой `grep -n -F -e '<цитата>' <файл>` (одинарные кавычки; для цитаты с
   апострофом — `grep -n -F -f <файл-с-цитатой>`), номер строки совпал. Команды и их вывод — в `<блок>-grep.log`
   (`A-grep.log` … `D-grep.log`). Итог в файле блока: «перепроверено N из N».

Большие HTML не читай целиком: ищи нужное `grep -n` и читай диапазоны строк.
