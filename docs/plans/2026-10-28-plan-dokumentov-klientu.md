Основа: мастер-промпт v6 (ППО → утверждение → КП → утверждение → оплата → аудит → ТЗ), rules/tz.md §1 (ТЗ после оплаты
базового пакета и аудита), решения менеджера 27.10 (маршрут ППО → КП → ТЗ; формат ППО — холст; утверждают Виталий и Роман).

## Поправки к видению менеджера
1. «Как было / как есть» → «как сейчас / как будет». История 2025 — 1 нейтральная строка без поиска виноватых.
   Без «как будет» клиенту нечего утверждать, а блокам КП не на что ссылаться.
2. «У клиента уже есть стоимость» — в репозитории оценки нет (у Дмитрия только «ТЗ ~8 ч, внедрение от 12 ч» по 1С).
   Цифры КП — только из оценки Анастасии (Б24) и Дмитрия (1С), положенной в репо.
3. Дата звонка с 1С-стороной: 15.10 или 22.10 — нужен ответ менеджера для слайда «Основание».
4. Клиент дважды просил ТЗ (15.10, 27.10). Закрываем так: ППО с «как будет» = то, что Виталий правит сейчас;
   первый платный блок КП = аудит 1С + ТЗ + базовая настройка Б24 (совпадает с планом Дмитрия: модель на типовой КА 2.5 → показ → комментарии → ТЗ).
5. Без новых встреч: ППО утверждается письменно; АТС и число пользователей — в сопроводительном письме.

## Решения менеджера 28.10 (заменяют поправки 2–5 выше)
- Стоимость проекта у менеджера на руках, проект оценён; цифры даёт менеджер на шаге КП.
- Даты в ППО: «встречи в октябре 2026 — по лидам, по сделкам, по 1С; письменные ответы компании»; точную дату звонка 1С не указываем.
- ЖЁСТКОЕ ПРАВИЛО: ТЗ и вся проектная документация пишутся только после подписания договора и оплаты. До оплаты клиенту — только ППО и КП. Аудит и ТЗ не предлагаются как бесплатный или предварительный шаг.
- Телефония: клиенту предлагаются готовые решения из имеющихся; не вопрос к клиенту.
- Число пользователей на стоимость не влияет; не вопрос к клиенту.
- Итоговый порядок: ППО → утверждение → КП блоками → договор и оплата → ТЗ и документация → реализация блоками → обучение → сдача.
