## Planning Contract

### Key Technical Decisions

- KTD1. Формат карточки. Меняется только `dd.q` сразу после `<dt>Главный вопрос</dt>`; `dd` под «Архивный главный вопрос» не трогается. Новый текст: «Точка <slug>:<N>: закрыто ответом клиента 08.10. Qxx: «<дословно>»» (несколько Q — через «; »). Сборка выводит на карту и в «Вопросы к встрече» только это поле (`docs/ppo/_common/build_proc.py:194-202`, `:269`, `:370`), поэтому ответ пишется в него, а не в новую пару `dt/dd`. Карточки С7 (Q35), С15 (Q36), С19 (Q37), С23 (Q38): к прежнему тексту `dd.q` дописывается « Ответ клиента 08.10: Qxx: «<дословно>»»; у С7 и С19 это идёт после закрытия Q24/Q25 и Q17/Q18. `dt «Уточнить по состояниям»` не меняется: `check_ppo.py:92,122` читает его через `dd_of`.
- KTD2. Пересборка только `python3 docs/ppo/build_all.py`; ручная правка собранных страниц запрещена.
- KTD3. Ответы копируются дословно из столбца «Ответ клиента» `otvety-klienta.md`; сырой файл в git не попадает. После ответа Q36 добавляется факт без толкования: «(доля оплаты до выезда для варианта по договору в ответе не названа)».
- KTD4. Формат aside и строк. В каждом `aside` фраза об открытом уточнении заменяется на «Закрыто ответом клиента 08.10:» и по одной фразе `Qxx: «<дословно>»` на каждый Q-id; ссылки на форму остаются. В строках S5, S8, S11, L5 статус `PROVEN / UNVERIFIED` → `PROVEN`. В строке S9 статус не меняется: её источник содержит ненадёжный фрагмент записи, который ответ Q30 не закрывает.
- KTD5. Проверка запускается без `--lidy`: флаг требует отдельного «да» владельца на лиды (`docs/ppo/check_ppo.py:7`), его нет. K9 падает уже на HEAD: 3 ошибки относительно базы 21125b3 (страницы лидов менялись в PR #21 и #37). Критерий для «Сделок»: ошибки только эти 3 K9, новых нет. U3 исполняется только после «да» владельца на лиды.
