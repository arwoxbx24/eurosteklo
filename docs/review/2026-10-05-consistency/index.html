Архитектурное решение

Контекст: клиентские оригиналы и тексты встреч → реестр источников → утверждение / узел / роль / условие → решение по пункту → уточнение. ППО остаётся отдельным производным представлением. Битрикс24, 1С и будущие интеграции находятся за границей этого документного аудита.

ADR: использовать существующие TSV и стабильные ID. Альтернативы — повторный опрос 110 узлов, сокращение только до прежних 7 вопросов, новая БД. Первый вариант повторяет известное; второй теряет частичные ответы; для третьего не показана потребность. Приоритеты выбора: ценность 40%, реализуемость 30%, безопасность 20%, экономичность 10%; численные оценки вариантов без измерения не выставлены.

Названия КИНТ, сервис.API, ИИ, amoCRM и имена из сообщения владельца не являются автоматически утверждёнными клиентскими интеграциями, ролями или требованиями. Их не добавляли в модель и вопросник без источника.
