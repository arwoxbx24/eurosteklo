# Спецификация 002: процесс компании верхнего уровня — как есть / как хочет / разрыв / варианты

**Создана**: 2026-09-28 · **Статус**: к исполнению · **Основание**: слово владельца 28.09 — «хочу понимать, как может работать процесс… построить полностью не можем, нет ответов на вопросы… показать часть: что происходит и как он хочет… подтверди, покритикуй, сними ещё раз верхнего уровня по всей информации»; «никакой технической терминологии — только бизнес-процессы».
**Закон**: `AGENTS.md` «Закон блокировки». **Предшественник**: spec 001 (пакет, коммит aa801f1).

## Методология (навыки проекта `.claude/skills/`, читать как справку)
- Обследование: `requirements-elicitation`, `stakeholder-analysis`, `meeting-facilitation`.
- Процесс: `process-mapping` (шаги, роли, входы/выходы), `process-states` (current-state / future-state, references/current-state-analysis.md, future-state-design.md), `ba-value-streams`.
- Разрыв и улучшение: `gap-analysis`, `process-optimization`.
- Проверка: `requirements-validation`.

## Требования
- **FR-101** Только язык бизнеса: шаг, роль, документ, решение, срок. Названия программ, полей, роботов — запрещены в основном тексте (допустимо в сноске «где видно»: кадр видео).
- **FR-102** Процесс по шагам верхнего уровня (от обращения клиента до завершения и сервиса). Для каждого шага: как сейчас (источник) · как хочет клиент (источник) · разрыв · что известно · что неизвестно (БЛОКИРОВАНО — вопрос) · варианты для обсуждения (2–3, плюсы/минусы/последствия, пометка «вариант для обсуждения, не факт»).
- **FR-103** Схема процесса: подтверждённые шаги и переходы — сплошной линией, неизвестные — пунктиром с номером вопроса.
- **FR-104** «Где клиент может ошибаться»: противоречия внутри доски, между доской и фактической работой, узкие места (нет ответственного, нет срока, потеря заявок), с источником.
- **FR-105** Вопросы по методике обследования: сгруппированы по шагам процесса, открытые вопросы (как, кто, что если), у каждого — какой разрыв/блок он снимает.
- **FR-106** Критика собранного: что из предыдущего пакета (spec 001) неверно или не подкреплено — список с решением.

## Спринты
Изоляция: блок читает всё, пишет только свой файл `docs/process/work/<блок>.md`.
- **Спринт 1** (параллельно): P-A как хочет клиент (доска: узлы, связи, комментарии) по шагам · P-B как сейчас (видео, сделки, речь) по шагам · P-C где клиент может ошибаться + критика пакета 001 (FR-104, FR-106).
- **КТ-1**: исполнитель сводит в `docs/process/2026-09-28-process-top-level.md` (FR-101…FR-105).
- **Спринт 2**: независимый критик (роль — скептичный собственник бизнеса клиента) → `docs/process/work/critic.md`.
- **КТ-2**: исполнитель вносит находки критика; журнал `docs/process/work/kt-log.md`, «упущено без решения: 0».

## Критерии успеха
- **SC-101** Каждый шаг содержит 7 блоков FR-102.
- **SC-102** Технических терминов в основном тексте — 0 (проверка по словарю: робот, триггер, воронка, стадия, поле, REST, вебхук, коннектор, CRM, API).
- **SC-103** Каждый вариант помечен «вариант для обсуждения».
- **SC-104** Неизвестное — только «БЛОКИРОВАНО» + номер вопроса; выдуманных фактов 0.
- **SC-105** ПДн 0.
