## 4. Метод на один пункт (точечно, только grep)

1. Из источника взять: ID (или `файл:строка`), тип пункта, согласованное решение — дословная цитата ≤25 слов, прежняя формулировка (если есть).
2. Подстрока проверки: дословный отрывок 3–8 слов из решения, который должен стоять на карте. Брать отрывок, лежащий в одной строке текста, без символов `<`, `>`, `&`. Для удаления — отрывок прежней формулировки. Для вопроса — начало вопроса или номер точки.
3. Команды — только `/usr/bin/grep` (не обёртка):
   - число: `/usr/bin/grep -c -F "<подстрока>" T1 T2 T3 T4 T5 T6 T7` (полные пути);
   - строки — только там, где число > 0: `/usr/bin/grep -n -o -F "<подстрока>" <файлы>`;
   - контекст при необходимости: `/usr/bin/grep -o -E ".{0,50}<подстрока>.{0,50}" <файл>`.
   Разрешено проверять несколько подстрок одной командой-циклом `for` в shell без создания файлов.
4. Повторная проверка перед статусом НЕТ или ТОЛЬКО ТЕХДОК (обязательна, оба результата в отчёт): заменить «ё» на «е» (карта часто пишет «е»), затем самое редкое ядро подстроки из 1–2 слов или номер точки.
5. Поиск в техдокументации: `git grep -c -F "<подстрока>" -- docs/ppo ':(exclude)<файл-источник пункта>'`.
6. Статус — ровно один, по приоритету сверху вниз:
   1. **НЕПРИМЕНИМО** — по правилам B/C/D или пункт по источнику не для карты (внутренний файл агентов, решение «не править»); причина — цитата `файл:строка`.
   2. **ПРОТИВОРЕЧИТ** — в T1–T7 найдена прежняя формулировка (для замены и удаления) или текст, прямо противоположный решению; указать `Tn:строка` и отрывок. Приоритет над всеми ниже.
   3. **НА КАРТЕ** — замена/вопрос: новая подстрока найдена в T1–T7 (`Tn:строка`); удаление: прежняя формулировка в T1–T7 = 0 (указать команду с 0).
   4. **ТОЛЬКО ТЕХДОК** — в T1–T7 0 (после повторной проверки), по шагу 5 найдено (указать файл).
   5. **НЕТ** — 0 в T1–T7 и 0 по шагу 5 (после повторной проверки).
7. Доказательство = команда + вывод (число). Без команды статус не ставится.
