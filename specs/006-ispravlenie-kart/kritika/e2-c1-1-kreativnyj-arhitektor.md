## 4. Жёсткая критика топ-3

**И4 — повестка в «С чего начать» (4,8).**
- Секция top5 одна на обе версии (BP:144-161): повестка 12–14 строк раздует короткую страницу; «С чего начать» (5 пунктов) и «повестка» — разные жанры. Смягчение: заголовок «Повестка встречи по лидам», подпункты — одной строкой.
- Повестка spec §4 — смешанная (лиды + сделки, 14 строк); встреча теперь «по работе с лидами» (Р-19) — отбор В×З c2-3 §1 придётся пересчитать, и мой набор точек — наш вариант, не проверен владельцем.
- Сама повестка — клиентский текст → по AGENTS:40 сливается только после «да».

**И1 — ручной проход по 15 парам (4,4).**
- Реестр пар c2-3 §2 опирается на В1–В4, которые владелец не утвердил, а index.html:53-55 уже выдал их за правило (Ф10). Строка 5 (повторный клиент → т.7) и 11в держатся на В2 — если владелец скажет иначе, ссылки поменяют направление.
- Приёмка «вручную по реестру» (spec 006:24) — без K10 ошибка ссылки не ловится; K1 проверяет только номера точек, не текст ссылок.
- «Один проход по карточке» нарушается: e2 сейчас + транскрипт потом = два прохода по тем же 40 карточкам.

**И10 — проверка А → H-1…H-3, H-7 (4,2).**
- Методика А у сделок дала 24 ошибки (spec 006:14); у лидов объём не подтверждён — может растянуть e2 и отодвинуть встречу (главное противоречие spec §3).
- Карта «предварительно утверждена» (журнал 28.09): найденные ошибки нельзя править без «да»; итог может быть «список ошибок без правок» — ценность ниже заявленной.
- H-7: SHA e2 появится только после слияния — строку e2 в том же PR не записать; метку облако не ставит (CHECKPOINTS, абзац про прокси).
