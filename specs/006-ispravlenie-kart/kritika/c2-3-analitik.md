## 3. Варианты ответа — окончательное правило. Ферми

Разводим две разные вещи (Г Т3 (а)/(б)):
- (а) **«А если…»** — сценарии-исключения, проверка полноты. Это не варианты ответа. Фиксированного числа нет, от 0 до N. У каждого пункта — источник или пометка «наш вопрос». Повтор заменяется ссылкой на владельца (§2). Сквозные пункты живут только в С23.
- (б) **Варианты ответа по существу** (чекбоксы П4): число = числу различимых версий в источниках (Д / ТЗ / СМ; портал — не источник) + «Другое — записать» + статус «не знает — кто знает». По классу В: СОВПАДАЕТ → 1 («так?»); ТОЛЬКО В ТЗ → 1 (формулировка ТЗ) с ответами «нужно / не нужно / так и работает / не знаю»; ТОЛЬКО НА ДОСКЕ → 1 + уточнения; ПРОТИВОРЕЧИЕ → 2–3 (если ТЗ и СМ совпадают, это одна версия); НЕТ НИГДЕ → 0, открытый вопрос.
- Число по источникам (моя разметка по TOCHKI, Б и В, по карточкам не сверено — не подтверждено): лиды 17 версий на 16 точек (≈ 1,1; т.1 и т.15 — по 2, т.6 — 0); сделки 63 на 29 точек (≈ 2,2; по 3 — С6, С7, С9, С10, С16, С18, С27). Всего ≈ 80 версий + 45 «Другое» ≈ 125 чекбоксов вместо 161 «А если…» по шаблону «4».

Ферми: новая повестка против полного прогона 45 точек.
- Полный прогон по номерам: 45 × 5–8 мин ≈ 3,8–6 ч разговора = 3–4 встречи по 90 мин. Из них ≈ 40 мин уходит на точки, где Роман не ответит (т.2, т.5 — портал; т.14, С22, С27, С28 — 1С), и ≈ 15–20 мин на повторы 14 пересечений. Рамка процесса (С24, граница, деньги, закрытие) складывается только к 3-й встрече.
- Повестка: встреча 1 ≈ 1,5 ч (19 точек + частично С7, С8, С10, С15, С17, т.16), встреча 2 ≈ 1,2–1,5 ч (22 точки, «ТОЛЬКО В ТЗ» — списком), 1С ≈ 1 ч с другим человеком. **Время Романа ≈ 2,7–3 ч вместо 3,8–6 ч.**
- Часы владельца: при 1 ч подготовки и разбора транскрипта на встречу — ≈ 7–8 ч против 7,5–10 ч; плюс ≈ 1 ч на повестку. **Экономия часов владельца мала (0–2 ч).** Главный выигрыш другой: время клиента (самый дефицитный ресурс) и календарь. Повестке нужны только П0 и устные С25/С29; П2–П5 (≈ 40–75 агентских ч по c1-3 §3) встречу не блокируют.

## 6. Готовый текст для spec.md (после «да» владельца)

**§2. Определения и владение вопросом** (рабочее правило раскладки вопросов, наше; это не процесс клиента; в журнал — после «да»)
- Лид — первичное обращение потенциального клиента из любого канала или рекламного источника, до квалификации. Сделка — работа с квалифицированным клиентом после конвертации лида (оба определения — владелец, 30.09.2026).
- Категории вопроса: ЛИДЫ · СДЕЛКИ · ГРАНИЦА (условие и момент конвертации) · СКВОЗНОЕ (правило одинаково для лида и сделки). Правило (срабатывает первое): 1) одинаково для обоих → СКВОЗНОЕ, владелец С23; 2) об условии или моменте перехода → ГРАНИЦА, владелец — лиды (т.8, т.9, т.15); 3) иначе — по объекту в момент события: сделки нет → ЛИДЫ, сделка есть (из лида или из 1С) → СДЕЛКИ; 4) два события в одном пункте → делим на подвопросы.
- Адресат — отдельная ось: Роман / собеседник по 1С / владелец проекта. 1С Роману по сути не задаём. Портал — не источник вопроса и варианта для клиента: такие части уходят в список аудита интегратора.
- В другом процессе вместо повтора — ссылка «см. точку N». Номера и карточки не удаляются. Реестр 15 пар (Г Т4 + т.15 ↔ С29) — `kritika/c2-3-analitik.md` §2; приёмка — вручную по реестру, без скрипта.
