## 2. Миграция формата ответов (П4) без потери

1. Старый ключ `evro-<slug>-answers` (`{N:{v,t}}`, `build_proc.py:227`) новый код **только читает**, никогда не пишет и не чистит. Новый формат — новый ключ `evro-<slug>-answers-v2`: `{_v:2, proc, points:{N:{st, var[], ifs{}, extra{}, note, date, qhash}}}`.
2. Чтение: если v2 нет, а v1 есть — перевод в памяти: «Подтвердил»→`confirmed`, «Иначе»→`other`, «Не знает»→`unknown`, `t`→`note`; запись v2 только при первом изменении. Неизвестные поля не удаляются.
3. `qhash` = хэш текста вопроса: после П1/П3 у изменённого вопроса старый ответ показывается с пометкой «вопрос изменён» (c1-2, F1).
4. Выгрузка `.md`: шапка `<!-- evro-answers v2 proc=<slug> -->`; выгружаются **все** ключи хранилища, включая точки без карточки (сейчас выгрузка идёт только по `article.q`, `build_proc.py:233`).
5. Импорт `.md`: чужой `proc` — отказ; слияние заменой по номеру; повторный импорт того же файла ничего не меняет; отчёт «принято / пропущено».
6. До выкладки П4 владелец нажимает «Сохранить ответы» на старой версии. Это единственная надёжная копия: `localStorage` для `file://` в разных браузерах — не подтверждено; были ли ответы 29.09 — не подтверждено.
7. Откат П4 безопасен для данных: старый код видит свой ключ нетронутым, v2 лежит рядом и вернётся после повторной выкладки.
