### П3. Варианты ответа — по источникам, а не по шаблону (Т3)

- Факт: у 37 из 40 точек ровно 4 варианта «А если…»; правила «4» нет нигде — шаблон автора (Г, Т3).
- Правило: число вариантов = числу различимых вариантов в источниках (доска / ТЗ / статусная модель) + «Другое — записать». Каждый вариант с пометкой источника или «наш вариант (гипотеза)». Допустимо от 1 (подтвердить/опровергнуть) до N.
- Приёмка: у каждого варианта есть источник или пометка.

### П4. Фиксированная система ответов на встрече (Т1, Т2)

- Сохраняем: точка на карте ↔ карточка вопроса (работает, владелец одобрил).
- Добавляем к каждой карточке: чекбоксы на варианты (можно отметить несколько — «так бывает и так»), статус точки (подтвердил / иначе / не знает / кто знает — записать), отметку по «А если…» и «Ещё», дату встречи.
- Выгрузка `.md` включает всё отмеченное; загрузка `.md` обратно (продолжить на другой встрече/в другом браузере).
- Ответы из браузера — рабочий черновик; источник для разблокировки точки — только транскрипт видео (закон блокировки).

### П5. Роли слева закреплены (Т5)

## 4. Как это исполняется

1. Перед П0 — точка отката: строка в `docs/CHECKPOINTS.md` (SHA текущей `main`).
2. Каждый приоритет — отдельное ТЗ по закону ТЗ (ТЗ → `/ce-doc-review` → `code-channel`), дробление на ≥3 блока (слои А/Б/В; точки; паспорт).
3. После каждого приоритета — сборка `build_all.py`, проверки HANDOFF (все вопросы подробной есть в короткой; точки ↔ карта; ПДн = 0), скриншоты, приёмка по таблице.
4. Обновлённая карта публикуется поверх той же ссылки (новых ссылок не создаём).
