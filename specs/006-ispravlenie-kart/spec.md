## 2. Определения и владение вопросом (рабочее правило раскладки; в журнал решений — после «да»)

- **Лид** — первичное обращение потенциального клиента из любого канала или рекламного источника, до квалификации. **Сделка** — работа с квалифицированным клиентом после конвертации лида (владелец, 30.09.2026).
- Это наше правило раскладки вопросов, а не процесс клиента. Расхождение с источниками выносится вопросом: ТЗ ФТ-2 «Квалификация заявки» и стадия портала стоят внутри сделки (`sanitized-tz.md:15`); на доске критерий конвертации — «все реквизиты»; сделка может возникнуть из 1С без лида.
- Категории вопроса (срабатывает первое): СКВОЗНОЕ (одинаково для лида и сделки, владелец — С23) → ГРАНИЦА (условие и момент конвертации, владелец — лиды) → ЛИДЫ → СДЕЛКИ. Адресат — отдельная ось: Роман / собеседник по 1С / аудит интегратора (портал клиенту не выносим).
- В другом процессе вместо повтора — ссылка «см. точку N». Точки и номера не удаляются, не перенумеровываются. Повторы в лидах (т. 3/13, 13/16, 7/11, 7/15) — это совпадающие пункты «А если…», а не точки: заменяются ссылкой, точки не объединяются. ## 5. Старое ТЗ ↔ доска Романа (из В, §2)

ТЗ = замысел 2024–2025 (AS-WAS, UNVERIFIED), доска = видение нового руководителя (предположение), статусная модель = прежняя интеграция с 1С. Класс строки → действие: СОВПАДАЕТ (9) → подтвердить одним вопросом; ТОЛЬКО В ТЗ (18) → «это ещё нужно?»; ТОЛЬКО НА ДОСКЕ (10) → уточнить как новое; ПРОТИВОРЕЧИЕ (18) → показать оба; НЕТ НИГДЕ (2) → открытый вопрос. Противоречие ≠ незнание Романа: процесс мог измениться после смены руководства, ТЗ мог быть неполным.
