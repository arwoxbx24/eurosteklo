# Спецификация 001: регламент подготовки пакета документов «Евростекло» к встрече с клиентом

**Создана**: 2026-09-28 · **Статус**: Утверждена к исполнению · **Атом bd**: dcfg-pszij
**Основание**: слово владельца 28.09.2026 — «мы будем разрабатывать спецификации, документы, бизнес-процессы, технические задания по данным, которые у нас есть»; «жёсткое требование технического задания и выполнение беспрекословно, никаких ручных правок».
**Закон проекта**: `AGENTS.md` «Закон блокировки: нет источника — нет утверждения».

## Сценарии и приёмка *(обязательно)*

### Сценарий 1 — Владелец понимает, как портал клиента настроен сейчас (P1)
Владелец открывает документ AS-IS и видит по разделам (воронки, стадии, поля, автоматизация, роли, интеграции, документы), что есть в портале сейчас, с кадром или таймкодом видео у каждого пункта.
**Почему P1**: без AS-IS нельзя честно сравнить с желаемым и вести встречу.
**Проверка**: любой пункт AS-IS находится по указанному кадру/таймкоду.
1. **Дано** видео владельца и его расшифровка, **когда** документ AS-IS готов, **тогда** каждый пункт имеет метку и ссылку на кадр или таймкод.
2. **Дано** раздел, о котором в видео нет сведений, **тогда** в нём стоит «Информации нет» и вопрос клиенту.

### Сценарий 2 — Владелец показывает клиенту пакет документов (P1)
Владелец открывает `docs/package/` и проводит встречу: карта возможностей, словарь сущностей, поток «лид → сделка завершена», схема систем, документ для клиента (как сейчас / как хочет / разрыв / вопросы).
**Проверка**: 5 файлов, в каждом метки и источники, ни одного выдуманного процесса.
1. **Дано** узел доски Miro, **когда** он попадает в поток ценности, **тогда** рядом ID узла или связи.
2. **Дано** требование клиента из комментария Miro, **тогда** рядом id комментария.

### Сценарий 3 — Агент заблокирован при нехватке данных (P1)
Агент, не найдя источник для утверждения, не строит гипотетический процесс, а пишет «Информации нет» и вопрос клиенту; пункт не переходит в ТЗ и регламент.
**Проверка**: в документах нет утверждений без метки.

### Пограничные случаи
- Речь в видео противоречит кадру → оба факта сохраняются, пункт UNVERIFIED, вопрос клиенту.
- AS-IS противоречит доске Miro → это разрыв «как есть / как надо», не ошибка; фиксируется в сверке.
- Упоминание 1С без документа → только UNVERIFIED.
- На кадре видны ФИО/телефон/email → в документ не переносятся (роль или «[скрыто]»).
- Кадр нечитаем → «не читается», без догадки.

## Требования *(обязательно)*

### Функциональные
- **FR-001** Разбор видео: кадры по смене сцены (≤150), индекс кадр↔таймкод, расшифровка речи с таймкодами. *Выполнено 28.09*: 35 кадров, `frames/index.csv`, `sharex-xDNm1l.srt`.
- **FR-002** Описание каждого кадра: раздел портала, дословные названия воронок/стадий/полей, автоматизация — только видимое.
- **FR-003** Документ AS-IS портала: речь (*выполнено*: `docs/as-is/2026-09-28-portal-as-is-speech.md`) + кадры → сводный `docs/as-is/2026-09-28-portal-as-is.md`.
- **FR-004** Сверка AS-IS ↔ TO-BE (доска Miro): таблица «узел/комментарий | есть сейчас: да/нет/информации нет | источник».
- **FR-005** Пакет `docs/package/`: 01 карта возможностей, 02 словарь сущностей, 03 поток ценности, 04 схема систем, 05 документ для клиента.
- **FR-006** Вопросы клиенту: ≤15, только по пунктам без источника, сгруппированы по темам.
- **FR-008** Поиск упущенного (полнота): каждый источник (35 кадров, SRT, 73 узла, 25 связей, 31 комментарий, 10 сделок, CSV, 5 JPG) сверяется с документами; факт источника, не попавший ни в один документ, — дописывается по ТЗ или помечается «вне объёма» с причиной. Результат — `docs/review/2026-09-28-coverage.md`: таблица «источник | элементов | покрыто | упущено».
- **FR-009** Сводный AS-IS заменяет в пакете допущения: факты кадров (воронки, стадии, коннектор 1С, поля 1С, открытые линии, BitrixGPT, роботы) переносятся в 01–05 с меткой PROVEN и номером кадра.
- **FR-007** Проверка противоречий в 3 круга перед выдачей: (а) источник каждого утверждения; (б) сверка документов между собой и с источниками; (в) независимый критик-рецензент. Находки закрыты или вынесены в вопросы.

### Регламент исполнения (жёсткий)
- **RG-001** Каждое изменение документа — только по ТЗ-файлу через канал исполнения (OpenCode, `code-channel`); главный агент правит только спецификацию и ТЗ. Ручные правки документов запрещены.
- **RG-002** Каждое ТЗ ссылается на пункт FR этой спецификации; работа вне FR = стоп.
- **RG-003** Независимые работы запускаются параллельно; зависимые — только после проверки входа командой.
- **RG-004** Приёмка каждого FR — командой с выводом (число); без вывода FR не закрыт.
- **RG-005** Б24 и Miro — только чтение. Конфиденциальное (`client-materials/private/`) — вне git. ПДн в документах = 0.
- **RG-006** Исключение, зафиксированное 28.09: описание кадров (FR-002) выполняют агенты с распознаванием изображений (канал исполнения изображения не читает), каждый пишет только свой файл `docs/as-is/frames/batch-NN.md`.

### Спринты и контрольные точки (владелец 28.09: «изолированные процессы, соединяем в контрольных точках»)
Правило изоляции: блок спринта только читает документы и пишет ОДИН свой отчёт `docs/review/<блок>.md`; документы правит только исполнитель контрольной точки по сводке отчётов.
- **Спринт 1** (параллельно): S1-A покрытие видео (35 кадров + SRT) · S1-B покрытие Miro (73/25/31) · S1-C покрытие CRM и файлов клиента (10 сделок, CSV, 5 JPG) · S1-D противоречия AS-IS ↔ бизнес-спецификация · FR-009 (идёт, правит пакет).
- **КТ-1**: все отчёты S1 есть, у каждого число «упущено/противоречий»; FR-009 сдан. Исполнитель вносит находки S1 в документы (FR-008, FR-007 а/б).
- **Спринт 2** (параллельно): S2-E круг (а) — метки у каждого утверждения · S2-F круг (в) — независимый критик пакета · S2-G проверка вопросов клиенту (≤15, каждый разблокирует пункт).
- **КТ-2**: исполнитель вносит находки S2; converge по SC-001…SC-006; коммит.

### Ключевые сущности
- **Источник**: файл клиента/выгрузка/видео с датой и путём.
- **Утверждение**: текст + метка (PROVEN/INFERRED/UNVERIFIED) + источник.
- **Вопрос клиенту**: тема, формулировка, блокируемые пункты.

## Критерии успеха *(обязательно)*
- **SC-001** AS-IS: ≥30 ссылок на таймкод/кадр; «Информации нет» — у каждого раздела без сведений.
- **SC-002** В `docs/` телефонов и email — 0.
- **SC-003** Пакет: 5 файлов, в каждом ≥1 метка; утверждений без метки — 0 (проверка кругом «а»).
- **SC-004** Вопросов клиенту ≤15, каждый ссылается на блокируемый пункт.
- **SC-006** Покрытие источников: упущенных фактов без решения — 0 (FR-008).
- **SC-005** Все 3 круга проверки пройдены, отчёт с числом находок и их закрытием.

## Допущения
- Видео — запись экрана портала владельцем-интегратором, речь — его комментарии.
- Доска Miro = желаемое состояние клиента (TO-BE).
- 1С: по кадрам видео (batch-02, batch-03) в портале есть «Коннектор к 1С» и поля «Номер 1С», «Статус из 1с» — PROVEN по кадру; порядок обмена и справочники 1С — UNVERIFIED, вопрос клиенту.
