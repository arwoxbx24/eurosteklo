Приёмочные сценарии:
1. **Дано** пункт реестра, на который карта уже ссылается (по номеру или по `файл:строка`), **когда** работа выполнена, **то** существующие `<li>` карточек не изменены ни на байт и вопрос не добавлен второй раз.
2. **Дано** пункт без ссылки на карте, у которого узел доски Miro совпадает с узлом карточки, **когда** работа выполнена, **то** в списке «Уточнить по состояниям» этой карточки есть новый пункт: 🟣, дословный вопрос из реестра, источник `<имя файла реестра>:<строка>`.
3. **Дано** пункт без ссылки и без совпадения узла, **когда** работа выполнена, **то** вопрос стоит строкой без номера точки: для лидов — в секции `id="povestka"`, для сделок — в секции `id="top5"` (видна на подробной странице сделок).

## 4. Требования

- **FR-001** Пункт реестра = строка таблицы, первая ячейка которой — `П-NN`, `Р-NN` или `К-NN`. Вопрос = ячейка столбца, который в ближайшей строке-заголовке выше (начинается с `| ID |`) называется «Вопрос клиенту».
- **FR-002** Текст вопроса переносится дословно: обрезаются только пробелы по краям и одна внешняя пара кавычек «…» (только если ячейка начинается с « и кончается на »; внутренние кавычки не трогаются); символы `&`, `<`, `>` экранируются. Перефразировать, сокращать, дополнять, объединять запрещено.
- **FR-003** Пункт, на который карта уже ссылается (правило 5.2), не трогается и не дублируется.
- **FR-004** Новый вопрос в карточке — пункт списка «Уточнить по состояниям»: `<li data-id="e<K>" data-src="доска">🟣 ВОПРОС <small class="src">ФАЙЛ:СТРОКА</small></li>`. `K` = наибольший номер `eN` среди всех `<li data-id>` этого списка (включая `data-see`) + 1; при нескольких вставках в одну карточку K растёт по порядку строк TSV. `ФАЙЛ:СТРОКА` — имя файла без каталога, например `k1-prepost.md:57`. Вставка — перед `</ul>` этого списка. Между `</dt>` и `<dd>` допускаются пробельные символы и перевод строки.
- **FR-005** Существующие `<li>`, `data-id`, номера и число точек, SVG-слои (`karta*.svg.html`), паспорт и `sostoyaniya.html` не меняются: ответы владельца в браузере привязаны к `data-id`. Новые кружки на схеме не рисуются — отметка новых вопросов только знаком 🟣 в тексте пункта.

## 5. Правила привязки (детерминированные, исполняет скрипт — не человек и не модель)

5.1. **Разбор.** Из трёх реестров берутся все строки по FR-001. Для каждой: `id`, `файл` (имя без каталога), `строка` (номер строки в файле, с 1), `вопрос` (по FR-001, FR-002), `стадия` (вторая ячейка — только для k1; у k2 и k3 пусто).

5.2. **«Уже на карте».** Статус `уже`, если в любом из семи собранных файлов (`docs/ppo/index.html`, `docs/ppo/sdelki/karta-sdelki.html`, `docs/ppo/sdelki/obsledovanie-sdelki.html`, `docs/ppo/sdelki/obsledovanie-sdelki-podrobno.html`, `docs/ppo/lidy/karta-lidy.html`, `docs/ppo/lidy/obsledovanie-lidy.html`, `docs/ppo/lidy/obsledovanie-lidy-podrobno.html`) встречается `id` (перед ним не буква и не дефис, после него не цифра) либо подстрока `<файл>:<строка>` (после неё не цифра). Проверка 5.2 идёт раньше 5.5.

5.3. **Точка по узлу доски.** Для пункта без статуса `уже` и не `пусто`. Сравнение регистрозависимое.
- ключи пункта (из всей строки, кроме ячейки вопроса): а) каждая цепочка из ≥ 9 цифр → последние 9 цифр; б) каждое 4-значное число, непосредственно перед которым стоит `…`, `к.`, `к.…` или `К`, → эти 4 цифры;
- ключи карточки (весь текст `<article class="card" id="tN">…</article>`): а) каждая цепочка из ≥ 9 цифр → последние 9 цифр, и, если цепочка начинается с `3458764`, — ещё её последние 4 цифры; б) каждое 4-значное число непосредственно после `к.` → эти 4 цифры;
- карточка подходит, если у неё и пункта есть хотя бы один общий ключ и в ней есть `<dt>Уточнить по состояниям</dt>`;
- порядок карт: стадия пункта начинается с «ЛИД» → сначала лиды, потом сделки; иначе сначала сделки, потом лиды. Берётся первая карта, где есть подходящая карточка; в ней — карточка с наибольшим числом общих ключей, при равенстве — с наименьшим номером. Статус `точка`. Остальные подходящие карточки обеих карт пишутся в колонку `also` (вопрос в них не вставляется).

5.4. **Нет точки.** Подходящих карточек нет → статус `повестка`; карта: `lidy`, если стадия начинается с «ЛИД», иначе `sdelki`.

5.5. Вопрос пуст или вся ячейка в круглых скобках → статус `пусто`.

5.6. **Основание** (колонка `basis`): для `уже` — `<имя собранного файла>:<строка>` первого вхождения; для `точка` — `ключ=<ключ>; <map>/tochki.html:<строка открывающего тега карточки>`; для `повестка` — `общих узлов нет`; для `пусто` — `пусто`.

## 10. Допущения

- Ссылка на пункт на карте (номер или `файл:строка`) считается достаточным признаком «уже заложено»: так карта построена бизнес-анализом, и переделывать это запрещено владельцем.
- `data-src="доска"` у новых пунктов означает происхождение: реестры составлены по узлам доски Miro; это не утверждение, что формулировка вопроса написана на доске.
- Вопрос реестра не в форме «А если…» допустим в списке флажков: сборщик и проверка форму текста не ограничивают.
- После сборки новые пункты считаются `уже` по ссылке `файл:строка`, которая видна на подробных страницах; на картах `karta-*.html` тот же пункт виден текстом со знаком 🟣 без ссылки (так устроен сборщик).
- Вопросы без точки у сделок видны только на подробной странице сделок (секция `top5`); у лидов — в повестке, ниже отреза «если осталось время».
- Отметка 🟣 — знак в тексте пункта, а не отдельный кружок на схеме: схема (SVG) не меняется, чтобы не сломать сборку и ответы владельца.
- Изменение собранных страниц лидов разрешено словом владельца 01.10 (ключ `--lidy`).
