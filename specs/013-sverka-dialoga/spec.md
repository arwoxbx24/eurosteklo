## §2 Пользовательские сценарии

1. **Владелец видит, что клиент ответил** (P1). Дано: две расшифровки и банк 285 вопросов. Когда: сверка закончена. Тогда: у каждого вопроса — статус, а у ответа — запись и таймкод.
2. **Владелец видит противоречия** (P1). Тогда: каждое противоречие названо с двумя сторонами: место в диалоге и строка документа (`TOCHKI.md`, `data.md`, анкета sct).
3. **Владелец получает вопросник клиенту** (P1). Если пробелы есть: отдельный HTML только с вопросами по пробелам. Если пробелов нет: запись «вопросник не нужен».
4. **Записи удалены после приёмки** (P2). Тогда: в копии Codex webm нет, а расшифровки на месте; копия в каталоге проекта защищена запретом `safe-delete` на сегмент `clients` (`tools/bin/safe-delete:36`) — удаляется только после снятия запрета владельцем контура инструментов (находка в bd), обход запрета запрещён.

**Пограничные случаи**: вопрос задан в другой точке (`data-see`) — статус `ССЫЛКА`; клиент ответил сам, без вопроса — `ОТВЕЧЕН` с таймкодом; ответ размыт — `ЧАСТИЧНО`; провал Hkb 418 с — не пробел (тишина, §0).

**Негативные примеры** (так нельзя):
- статус `ОТВЕЧЕН` без таймкода;
- одна строка на точку вместо строки на каждый вопрос (ошибка Codex К3);
- вопрос про 1С или DNS в вопроснике клиенту;
- новая ссылка b244 без запроса владельца (владелец 04.10: «короткие ссылки отчётов не нужно присылать если я об этом не запросил»).

## §3 Требования

- **FR-001** Банк = 285 вопросов §0; каждый — ровно одна строка с `id` вида `L|S-t<N>-q|e<M>`.

- **FR-003** `ОТВЕЧЕН`, `ЧАСТИЧНО`, `БЕЗ-ОТВЕТА` — с записью, таймкодом и меткой из расшифровки.
- **FR-004** Противоречие `да` — с источником `<файл>:<строка>` или `<запись> <таймкод>`.
- **FR-005** `ЧАСТИЧНО`, `БЕЗ-ОТВЕТА`, `НЕ-ЗАДАН` и строки с противоречием — с вопросом клиенту ≤150 знаков, без внутренних кодов. Строки `ВНЕ-1С`, `ВНЕ-DNS`, `ССЫЛКА` — без противоречия и без вопроса.
- **FR-006** Темы диалога вне банка — отдельная таблица (B7).
- **FR-007** Сведение механическое: склейка таблиц и pandoc. Без пересказа агентом.
- **FR-008** Вопросник HTML создаётся, только если пробелов больше 0. Если пробелов 0, пишется `sverka/voprosnik-ne-nuzhen.txt` со строкой `пробелов 0`.
- **FR-009** Все выводы лежат в `client-materials/private/2026-10-04-dialogue/sverka/` (вне Git). Не публикуются, ссылок нет.
- **FR-010** Записи webm удаляются после PASS проверки только через `tools/bin/safe-delete file` (бэкап 14 дней). ## §4 Критерии успеха

- **SC-001** Строк в B1–B6 = 76 + 40 + 47 + 45 + 43 + 34 = 285; множество `id` совпадает с банком из HTML (0 лишних, 0 недостающих).
- **SC-002** 100 % строк `ОТВЕЧЕН|ЧАСТИЧНО|БЕЗ-ОТВЕТА` имеют таймкод, который есть префиксом строки в названной расшифровке.
- **SC-003** Выборка из 30 случайных строк `ОТВЕЧЕН|ЧАСТИЧНО`: смысл `ответ_кратко` подтверждается текстом расшифровки ±60 с от таймкода — не менее 28 из 30.
- **SC-004** 100 % строк с противоречием `да` имеют источник, строка которого существует (номер ≤ числа строк файла) или таймкод которого есть в расшифровке.
- **SC-005** Число вопросов в вопроснике = числу строк-пробелов (B1–B6: статус `ЧАСТИЧНО|БЕЗ-ОТВЕТА|НЕ-ЗАДАН`, а также `ОТВЕЧЕН` с противоречием `да`; плюс B7 с вопросом ≠ `—`). В вопроснике 0 вхождений «1С», «DNS», «t<N>-». Если пробелов 0, есть `voprosnik-ne-nuzhen.txt`, а вопросника нет.
- **SC-006** Отчёт `otchet.html` содержит все 285 строк и все строки B7.
- **SC-007** После удаления: `.webm` в копии Codex — 0 файлов; в копии проекта — 2 файла и открытая находка-блокер в bd; `transcripts-tools/*` и `transcripts/*/full.json` на месте.
- **SC-008** Коммит ветки: только `specs/013-sverka-dialoga` и `docs/plans/2026-10-05-sverka-dialoga-requirements.md` (`git add` поимённо); gitleaks — 0 находок; данных клиента в Git нет.
- **SC-009** Ответ каждого блока: ровно одна пара `---TSV---`/`---END---`, после неё строка `итого:`; в каждой строке данных 9 полей (B7 — 10); число строк данных = ожидаемому из ТЗ блока.
