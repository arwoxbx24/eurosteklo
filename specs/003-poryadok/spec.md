**Создана**: 28.09.2026 · **Статус**: черновик, ждёт «да» владельца · **Основание**: жёсткий приказ владельца 28.09 «работать строго через спецификацию, навести порядок, шаг за шагом разобрать клубок».
**Регламент**: spec 001 (раздел «Регламент исполнения»). **Замечания**: `docs/meetings/ЗАМЕЧАНИЯ-статус.md`; дословная переписка текущей сессии — `docs/meetings/переписка-сессия-c5329ec0.md` (приоритет 1).

## Сценарии и приёмка *(обязательно)*

### Сценарий 1 — Владелец видит одно ясное состояние всего (P1)
Владелец открывает один файл и по каждой вещи (материал клиенту, готовое решение, песочница, git, мусор) видит: что требовалось → что есть → чего не хватает → один шаг исправления.
**Приёмка**: 1) каждая строка таблицы ниже имеет факт с доказательством (файл, ссылка, команда); 2) ни одной строки «не проверено» без причины.

### Сценарий 2 — Исправления идут по одному, с «да» (P1)
Агент берёт одну строку таблицы, исполняет её шаг, показывает доказательство и ждёт «да» владельца перед следующей.
**Приёмка**: 1) в bd одна задача на строку; 2) у закрытой задачи — команда и её вывод; 3) между шагами — «да» владельца в переписке.

### Сценарий 3 — Готовое не ломается (P1)
Опубликованное и одобренное (ссылки LINKS.md, схема DwW) не пересобирается и не получает новых ссылок.
**Приёмка**: 1) ссылки LINKS.md не меняются; 2) содержимое опубликованных объектов меняется только по отдельному «да».

### Пограничные случаи
- Шаг требует действия, которое машина запрещает (удаление, копирование кода, GitHub) → строка «заблокировано: <команда> → <отказ>», вопрос владельцу, без обхода.
- Найдена новая проблема по ходу → новая строка таблицы, ноль действий до «да».
- Требование владельца из текущей сессии противоречит прошлой → действует текущая сессия.

## Требования *(обязательно)*

### Функциональные
- **FR-001** Таблица «требование → факт → расхождение → шаг» (ниже) покрывает все 6 областей приказа.
- **FR-002** Три зоны разделены: песочница — только тесты и удаляется после записи результата; рабочий проект — только материалы клиента и спецификации; `clients/tools/` — только инструменты.
- **FR-003** Готовое решение (drawio-ai-kit) имеет записанное рабочее состояние: что работает, что нет, чем подтверждено.
- **FR-004** Каждое требование ТЗ правки схемы BPMN проверено на сохранённом исходнике.
- **FR-005** Git проекта: ноль незакоммиченных рабочих файлов; наличие удалённого репозитория — решение владельца.
- **FR-006** Мусор (временные ТЗ, скриншоты, логи) — перечислен и убран после «да».
- **FR-007** Каждое ТЗ в opencode проходит проверку спецификации (`ce-doc-review`) до отправки.

### Регламент исполнения
Один шаг = одна строка таблицы = одна задача bd. Шаг → доказательство → «да» владельца → следующий. Без пересборки готового. Без новых ссылок.
